# Plan: Add Structured Logging to All Print Requests

## Current State
The codebase has **4 print request entry points** that currently use inconsistent `console.log` logging:

| Entry Point | Location | Current Logging |
|-------------|----------|-----------------|
| Manual API: `POST /api/orders/:id/print-bill` | `routes.ts:582-625` | Only error logging on catch |
| Auto-print after order creation | `routes.ts:193-243` | Basic `console.log` with response |
| Auto-print during status polling | `IikoOrderStatusService.ts:179-235` | Basic `console.log` with response |
| Core `printBill()` service method | `IikoOrderStatusService.ts:67-93` | Has `[PRINT_BILL]` prefix logs for request/response |

## Proposed Changes

### 1. Enhance `IikoOrderStatusService.printBill()` (Core Service)
- Use Fastify's structured logger via dependency injection
- Add context: `trigger` (manual/auto_creation/auto_polling), `orderId`, `iikoOrderId`, `organizationId`, `userId`
- Log request payload, response, duration, success/failure
- Return structured result with metadata

### 2. Update Manual Print Endpoint (`routes.ts:582-625`)
- Use `request.log.info()` for structured logging
- Log: user ID, order ID, trigger type "manual", request/response
- Keep audit log creation (already exists)

### 3. Update Auto-Print After Creation (`routes.ts:193-243`)
- Use `request.log.info()` (available in route handler context)
- Log: trigger type "auto_creation", order IDs, request/response
- Add timing/duration logging

### 4. Update Auto-Print During Polling (`IikoOrderStatusService.ts:179-235`)
- Inject logger into service or use `app.log` from decorated app
- Log: trigger type "auto_polling", order IDs, request/response
- Since this runs in background, use `app.log` (decorated on Fastify instance)

### 5. Centralized Logger Access Pattern
- Pass logger instance to `IikoOrderStatusService` constructor (optional, for background jobs use `app.log`)
- In route handlers, use `request.log` for request-scoped logging
- For background polling, use `app.log` via decorated app instance
