## Implementation Plan for Resolving 500 Error on Menu Sync

**Background**
- The `POST /api/iiko/sync/menu` endpoint throws a generic `500 Internal Server Error` when the organization record required for synchronization is missing. This occurs because `IikoNomenclatureService.syncMenu` checks for an organization with the ID from `env.IIKO_ORGANIZATION_ID` (or a query param) and throws an `Error` if not found, which is caught by Fastify's error handler and transformed into a 500.

**Root Cause (as identified)**
- The `IIKO_ORGANIZATION_ID` environment variable is set, but the corresponding organization record has not been synchronized into the database. Hence `prisma.organization.findUnique` returns `null` and the service throws the generic error.

**Plan**
1. **Validate Environment Configuration**
   - Ensure that `.env` (or the environment in which the server runs) contains a valid `IIKO_ORGANIZATION_ID` value matching the iiko organization you intend to sync.
   - If the variable is missing or empty, add the correct ID (e.g., `IIKO_ORGANIZATION_ID=your-iiko-org-id`).

2. **Synchronize Organizations Before Menu Sync**
   - Call the dedicated endpoint that populates the required reference data:
     ```http
     POST /api/iiko/sync/directories
     Authorization: Bearer <admin‑jwt>
     ```
   - This endpoint creates/updates `organization`, `terminalGroup`, `orderType`, and `paymentType` records. It must be executed at least once (or whenever the organization data changes) before attempting the menu sync.
   - Verify the response includes the newly created organization and that `prisma.organization` now contains a row with `iikoId` equal to `IIKO_ORGANIZATION_ID`.

3. **Retry Menu Synchronization**
   - After the directories are synced, trigger the menu sync again (via the UI button or directly):
     ```http
     POST /api/iiko/sync/menu
     Authorization: Bearer <admin‑jwt>
     ```
   - The endpoint should now find the organization, perform the product sync, and return a `200` with `{ synced, revision }`.

4. **Optional – Improve Error Reporting (recommended for future robustness)**
   - **Add explicit validation** in `IikoNomenclatureService.syncMenu`:
     ```ts
     if (!organization) {
       const err = new Error("Organization not found – sync directories first");
       // Attach a custom status code (e.g., 400) via a property or a custom error class.
       (err as any).status = 400;
       throw err;
     }
     ```
   - **Update the route handler** (`iikoRoutes.ts`) to detect this status and return a 400 with a clear message instead of a generic 500.
   - **Add a test case** in `routes.integration.test.ts` that asserts a 400 response when the organization is missing.
   - This makes debugging easier for developers and surfaces the root cause directly to the client.

5. **Verification Steps**
   - Check server logs: after the fix, a successful menu sync should log a normal `info` entry (no 500).
   - Confirm that `prisma.apiError` does not receive a new entry for the menu sync attempt.
   - In the UI, the “Обновить меню” button should complete without error and display the number of synced items.
