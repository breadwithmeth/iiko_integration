**Implementation Plan**

1. **Add shared validation helper (frontend)**
   - Create file `apps/web/src/utils/product.ts`.
   - Export:
   ```ts
   import type { ProductDto } from "@iiko-call-center/shared";
   /**
    * Returns true if the product is a DISH and has a positive price.
    */
   export const isValidDish = (product: ProductDto): boolean =>
     product.type === "DISH" && product.defaultSalePrice > 0;
   ```

2. **Update NewOrderPage**
   - File: `apps/web/src/pages/NewOrderPage.tsx`.
   - Import the helper:
   ```ts
   import { isValidDish } from "../utils/product";
   ```
   - Replace the line that builds `productItems` (currently `const productItems = products.data?.items ?? [];`) with:
   ```ts
   const productItems = (products.data?.items ?? []).filter(isValidDish);
   ```
   - (Optional) Guard `addProduct` so it returns early if the product fails the check (should never happen because UI is filtered).
   - Adjust any UI messages if `productItems` becomes empty.

3. **Add server‑side validation helper**
   - Create file `apps/api/src/services/productValidator.ts`.
   - Export:
   ```ts
   import type { Prisma } from "@prisma/client";
   /**
    * Returns true if the product record is a DISH and its price is greater than zero.
    */
   export const isDishWithPositivePrice = (product: Prisma.Product): boolean =>
     product.type === "DISH" && Number(product.defaultSalePrice) > 0;
   ```

4. **Update order creation endpoint**
   - File: `apps/api/src/modules/orders/routes.ts`.
   - Import the validator: `import { isDishWithPositivePrice } from "../../services/productValidator.js";`
   - After the existing product fetch (lines ~84‑88) insert validation:
   ```ts
   if (products.some(p => !isDishWithPositivePrice(p))) {
     return reply
       .code(400)
       .send({ message: "One or more ordered products are not DISH or have zero price" });
   }
   ```
   - Keep the existing existence check.

5. ** tighten Zod schema for product price**
   - In `orderRoutes.ts` change the `price` field in `itemSchema` from `z.number().nonnegative()` to `z.number().positive()` to reject zero‑price items early.
   - This applies only to the main product price (modifiers have their own schema).

6. **Add backend test**
   - Create/extend test file `apps/api/src/test/orderRoutes.test.ts`.
   - Steps:
     * Insert a product with `type: "NON_DISH"` (or `type: "DISH"` but `defaultSalePrice: 0`).
     * Attempt to POST an order containing that product via the API client.
     * Assert the response status is 400 and the body contains the error message from step 4.
   - Ensure test data is cleaned up after the test.

7. **(Optional) Add UI test**
   - Using React Testing Library, render `NewOrderPage` with a mocked `useProducts` hook that returns a mixture of DISH and non‑DISH items, some with zero price.
   - Assert that only items satisfying `isValidDish` appear in the rendered list.

8. **Run lint/type‑checking**
   - Execute `npm run lint` and `npm run typecheck` to confirm no TypeScript errors.

9. **Commit & PR**
   - Create branch `feat/order-dish-filter`.
   - Commit all changes with clear messages.
   - Push and open a PR for review.

This plan implements both UI‑side filtering and server‑side validation, ensures that only products of type `DISH` with a positive price can be part of an order, and adds test coverage to prevent regressions.
